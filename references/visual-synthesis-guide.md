# Visual Content Synthesis Guide

## Purpose

This guide defines Stage 4.5 of the interview-based-learning pipeline: transforming the raw extraction data (`knowledge.json`) into a **synthesized content structure optimized for visual presentation** (`visual_content.json`).

The core insight: Markdown reports benefit from Claude's narrative synthesis because Claude writes them directly. HTML outputs are generated by Python scripts that mechanically iterate over `knowledge.json` — they have NO synthesis step. Stage 4.5 fills this gap.

## Design Philosophy

### The Three-Layer Information Architecture

Visual content must support **three reading depths**, each building on the previous:

| Layer | Name | Time | Content |
|-------|------|------|---------|
| 1 | At a Glance | ~3 min | Core thesis + key takeaways + most surprising insight. A reader should grasp the interview's essence from this layer alone. |
| 2 | The Argument | ~10-15 min | Theme-organized narrative sections. Each theme has synthesized prose (not extracted bullet points) + curated supporting evidence. |
| 3 | The Evidence | On demand | Complete data: all quotes, data points, predictions. Available for deep reference but not pushed to the reader. |

### Theme-Driven, Not Chronology-Driven

The MD deep-dive report follows chronological order (segment by segment). The HTML outputs should follow **conceptual order** (theme by theme), because:

- Readers browse HTML non-linearly — they jump to what interests them
- Themes represent the **synthesized knowledge** — the "so what" of the interview
- Chronological browsing is still available as a secondary navigation mode

### Curation Over Exhaustion

`knowledge.json` contains 124 insights, 130 quotes, 126 data points. Showing ALL of these in a visual interface is overwhelming and counterproductive. The visual outputs must:

- **Select** the top ~30% of items by importance/significance
- **Prioritize** items that support the cross-cutting themes
- **Group** related items under thematic headings
- **Hide** the full dataset behind progressive disclosure ("Browse All Evidence")

### Map-Specific Principles

A knowledge map should reveal **structure and relationships**, not just hierarchy:

- **Center**: The interview's core thesis (the "one big idea")
- **Primary ring**: Cross-cutting themes (the synthesized insights)
- **Secondary ring**: Supporting arguments for each theme
- **Tertiary ring**: Curated evidence (1-2 best quotes/data points per argument)
- **Cross-links**: Connections between related ideas across themes (supports, contrasts, extends)

This is fundamentally different from the current "segment → insight → quote" mechanical hierarchy.

## Input

Stage 4.5 takes two inputs:

1. **`knowledge.json`** — The merged extraction data from Stage 4, containing:
   - `metadata` (title, guest, duration, etc.)
   - `segments[]` (12 segments with insights, quotes, data_points, contradictions, predictions)
   - `cross_cutting_themes[]` (7 themes with descriptions and segment references)
   - `open_questions[]`

2. **The deep-dive Markdown report** (`report-*.md`) — The synthesized narrative report from Stage 5 Output 2, containing:
   - Executive Summary (synthesized narrative)
   - Topic-by-topic analysis (narrative paragraphs per segment)
   - Cross-cutting themes analysis (synthesized prose)
   - Predictions summary table
   - Complete quote collection

## Process

### Step 1: Extract the Core Thesis

Read the Executive Summary from the MD report. Identify the **single most important claim** the interview makes — the "one big idea" that unifies everything. Write it as:

- `core_thesis`: One concise sentence
- `core_thesis_elaboration`: One paragraph expanding the thesis with context

### Step 2: Extract Key Takeaways

From the TL;DR markdown report, extract the 5-7 key takeaways. These should be the synthesized claims (not raw quote text). Each takeaway should be a self-contained proposition.

### Step 3: Build Theme Structures

For each cross-cutting theme in `knowledge.json`:

1. Read the theme's description and the narrative analysis from the MD report
2. Write a `summary` (1-2 sentences) and `narrative` (2-3 paragraphs of synthesized prose, like the MD report's style)
3. Scan ALL segments to find insights that support this theme (not just the segments listed in `appears_in_segments`)
4. For each supporting insight, assign an `importance` score (1-5):
   - 5: Core to the theme, would be cited in any summary
   - 4: Strongly supports the theme with compelling evidence
   - 3: Relevant but not essential
   - 1-2: Tangentially related
5. Select the top 3-5 insights per theme (those with importance 4-5)
6. For each selected insight, pick the **single best quote** that illustrates it
7. Note which other themes this theme relates to (`related_themes`)

### Step 4: Build Segment Synopses

For each segment, write a `synthesis_narrative` — a 1-2 paragraph synthesis that captures what this segment contributes to the overall interview narrative. This is NOT the same as the segment `summary` (which is descriptive). The synthesis narrative should explain **why this segment matters** in the context of the whole interview.

Also note which themes each segment belongs to.

### Step 5: Build Map Data

Transform the theme structures into a map-specific format:

1. `central_thesis`: The core thesis, formatted for a central node label (max 60 chars)
2. `theme_nodes[]`: Each theme as a map node with:
   - `name`: Theme name (max 25 chars for display)
   - `color`: Assign from a fixed palette
   - `arguments[]`: Top 2-4 supporting insights with their best evidence
3. `cross_links[]`: Connections between arguments in different themes:
   - `source`: "theme_id.arg_index" 
   - `target`: "theme_id.arg_index"
   - `relation`: "supports" | "contrasts" | "extends"

### Step 6: Curate Quotes

From the complete quote collection, select the 15-25 most impactful quotes. Criteria:
- Supports a cross-cutting theme
- Is surprising, pithy, or revealing
- Works as a standalone pull-quote
- Represents diverse topics (don't cluster all from one segment)

### Step 7: Select Highlighted Content Per Theme

For each theme, select:
- 3-5 highlighted insights (the ones with importance 4-5)
- 2-3 highlighted quotes (the best illustrations)
- Related data points (facts that support the theme's claims)

## Quality Rules

### Synthesis, Not Rearrangement

- The `narrative` field for each theme must be **original synthesized prose**, not a concatenation of insight `claim` fields
- The `synthesis_narrative` for each segment must explain **why this segment matters**, not just what it contains
- Every piece of prose should read like it was written by someone who **understood the interview** and is explaining it to a friend

### Source Fidelity

- All claims must be traceable to specific segments and timestamps in `knowledge.json`
- Quotes must remain verbatim from the transcript
- When synthesizing across multiple segments, cite all source segments
- Never invent claims not present in the source material

### Curation Discipline

- Maximum 5 highlighted insights per theme
- Maximum 3 highlighted quotes per theme  
- Maximum 25 curated quotes total
- Maximum 4 arguments per theme in map_data
- Maximum 2 evidence items per argument in map_data
- Quality over quantity: 3 excellent insights > 15 mediocre ones

### Map Data Constraints

- `central_thesis`: ≤60 characters (must fit in a circular node)
- Theme node `name`: ≤25 characters
- Argument `claim`: ≤50 characters
- Evidence `text`: ≤120 characters (full text in tooltip)
- Maximum 8 cross-links total (too many becomes visual noise)
- Cross-links must connect arguments in DIFFERENT themes

### Visual Hierarchy

- Theme `importance` determines display order and visual prominence
- Insight `importance` (1-5) determines card size/position within a theme
- Higher importance = more prominent visual treatment
